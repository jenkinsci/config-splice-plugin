The replacement, as a literal.

Do not hard-code a secret here. A literal written into this field is persisted: with the job configuration in a Freestyle job, and with the build record in a Pipeline, where it is shown by Pipeline visualisation as well. Either way it is readable by anyone who can read the job. Use the credential field below for anything sensitive.

Referring to a credential through an environment variable is safe, and is a good option when one credential supplies more than one value. In a Pipeline: 

withCredentials([usernamePassword(credentialsId: 'my-secret',
                                  usernameVariable: 'MY_USER',
                                  passwordVariable: 'MY_PASS')]) {
    configSubstitution(targets: [[files: ['*.json'], format: 'json',
        substitutions: [
            [path: 'user', value: env.MY_USER, type: 'string'],
            [path: 'pass', value: env.MY_PASS, type: 'string']
        ]]])
}

Inside withCredentials the value is masked in the build log, and Pipeline replaces it with ${MY_PASS} before storing the step arguments, so it is not persisted. A Freestyle job needs an equivalent credential-binding option in its build environment to achieve the same thing. For a single Secret Text the credential field below is simpler on either surface.

Always written as text here; how it is emitted into the file is decided by the value type.
